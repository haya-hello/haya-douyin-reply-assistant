# 私信批次 V1.1

## 使用

- “先看看私信准备怎么回，别发送” → `Start-ReplyAssistant.ps1 -Action dm-preview`。
- 当次明确说“帮我回复最近三天的私信” → `Start-ReplyAssistant.ps1 -Action dm-reply -ConfirmSend`。
- 私信体检：`Start-ReplyAssistant.ps1 -Action doctor-dm -Online`。
- 人工接管清单仍用 `-Action handoffs`，按channel区分评论和私信。

不会启用旧DMShoot无限自动回复，不驻守、不自动跑下一批。私信不依赖Chrome评论桥接；使用已保存的DMShoot凭据，临时打开独立Edge读取新鲜历史快照。快照失败就停止，不能用陈旧缓存直接发送。

## 执行边界

1. 校验本人账号与完整签名；只处理本人参与的一对一已有入站会话。
2. 使用结构化Protobuf字段解析消息，不再通过扫描正文猜测收件人。消息时间未知时不冒充“刚收到”。
3. 最后一条必须是最近72小时尚未回答的入站；连续入站合并成一条回复。最新消息已经由本人发送则跳过。
4. 同会话最多自动回复2次。第二次必须有上次尝试之后的新入站；重启不重置。此前已经确认的系统测试回复会迁入计数账本。
5. 生成后再抓新快照；本人已回复、出现新问题、目标变化则取消旧草稿。仍无法完全消除发送瞬间的外部人工操作竞态。
6. 每批最多5个会话，和评论共用运行锁及至少60秒发送间隔；不是平台免封保证。
7. 缺资料、敏感内容、非文本消息或已达上限，交给本人。不确定项后续不自动重新放行。
8. 发送前持久化attempt，发送必须同时拿到接口OK与匹配本人、会话、正文、时间的回显；否则整批停止且阻断后续重试。

## 验收事实

- 全模块37项测试通过：评论回归、恢复回归、私信轮次、新入站条件、手动回复竞态、共享锁、整批停止、收件人校验、接口确认加回显验证。
- 已从真实账号读取99条结构可验证的历史消息，其中52条为本账号发出；当时没有最近72小时内可安全自动处理的候选。
- 只读取/预览，不为验收向真实联系人批量发送。底层单条发送此前已实测成功，新批次首次真实外发仍需实际有候选时进行，不把模拟测试当作真实送达。
- 历史初始化快照不是全量历史，不能保证覆盖全部会话。当前仅处理快照中可验证的消息。
- 新发送回显ID写入统一账本，后续学习库导入时排除已知系统生成的回复。

V1.0.0包保持不变。当前版本及检查结果以version.json和data/qa报告为准。
